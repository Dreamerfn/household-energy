# Как из минутных измерений получается график расхода

Счётчик записывает среднюю мощность дома каждую минуту. Верхняя панель графика показывает, когда в течение дня росла нагрузка. Чтобы узнать, сколько электроэнергии набралось за сутки, программа переводит каждое показание в энергию за минуту и суммирует эти значения. Этот результат виден на нижней панели.

## Входные данные и единицы измерения

Набор описывает один дом во Франции. Каждая строка относится к одной минуте. Словарь `FIELDS` в `prepare.py` задаёт соответствие между исходными и выходными именами.

| Вход | Колонка в minutes.csv | Содержание |
|---|---|---|
| `Date`, `Time` | `timestamp` | Дата и время одной минуты. Исходный порядок — день, месяц, год. В CSV год стоит первым. |
| `Global_active_power` | `active_kw` | Средняя активная мощность всего дома за минуту, кВт. Из неё рассчитывается расход. |
| `Global_reactive_power` | `reactive_power` | Средняя реактивная мощность. Значение сохранено в шкале источника, где единица обозначена как kW. |
| `Voltage` | `voltage_v` | Среднее напряжение, В. |
| `Global_intensity` | `current_a` | Средняя сила тока, А. |
| `Sub_metering_1` | `sub_1_wh` | Энергия кухонного оборудования за минуту, Вт·ч. |
| `Sub_metering_2` | `sub_2_wh` | Энергия оборудования прачечной за минуту, Вт·ч. |
| `Sub_metering_3` | `sub_3_wh` | Энергия водонагревателя и кондиционера за минуту, Вт·ч. |

Показания трёх отдельных счётчиков уже входят в общий расход дома. Они сохраняются для самостоятельного анализа. [Описание измерений в UCI](https://archive.ics.uci.edu/dataset/235/individual+household+electric+power+consumption)

## Как работает prepare.py

### 1. Чтение и очистка в clean(source)

`pd.read_csv` разбирает TXT по разделителю `;` и выбирает нужные столбцы. Можно передать и ZIP с единственным файлом данных. Пустые поля и `?` pandas читает как пропуски. В памяти это `NaN`, а в выходном CSV — пустое поле. Подлинное нулевое потребление сохраняется числом 0.

1. `pd.to_datetime` соединяет дату с временем по формату `%d/%m/%Y %H:%M:%S`. Строки с неразбираемой меткой или ненулевыми секундами исключаются. Принятые метки становятся индексом таблицы.
2. `pd.to_numeric` переводит семь измерительных полей в числа. Нечисловой текст, бесконечности и отрицательные показания заменяются пропуском. Напряжение также должно быть больше нуля. Проверка действует на отдельные ячейки, поэтому корректные поля той же строки сохраняются.
3. При повторе временной метки программа рассматривает каждый столбец отдельно. Например, если для одной минуты пришли `2` и пропуск, остаётся `2`. Если пришли `2` и `3`, возникает конфликт и в результате остаётся пропуск. Одинаковые показания дают одно значение. Это защищает суточную сумму от двойного счёта.
4. Для проверки скачков мощности вычисляется ориентир по напряжению и току. Если `active_kw > voltage_v × current_a / 1000 + 0.10`, активная мощность за эту минуту помечается пропуском. Допуск 0,10 кВт выбран в проекте как практическая поправка для сравнения усреднённых измерений. Это эвристика, её можно изменить в `POWER_TOLERANCE_KW`. При отсутствии напряжения или тока эту проверку выполнить нельзя. Высокий пик сохраняется, если он согласуется с имеющимися измерениями.

Функция возвращает отсортированную минутную таблицу и словарь счётчиков. По счётчикам можно понять, сколько записей затронул каждый шаг. У них разные единицы подсчёта.

| Метрика в quality.csv | Что именно посчитано | Результат для архива |
|---|---|---:|
| `source_rows` | Все строки данных, прочитанные из файла | 2 075 259 |
| `invalid_time_rows` | Строки с неверной меткой или ненулевыми секундами | 0 |
| `missing_input_cells` | Изначально пустые измерения в строках с принятой меткой | 181 853 |
| `invalid_numeric_cells` | Дополнительные ячейки, исключённые при числовой проверке | 0 |
| `extra_duplicate_rows` | Число строк сверх одной на каждую принятую временную метку | 0 |
| `conflicting_duplicate_cells` | Пары «минута, столбец» с несколькими разными корректными значениями | 0 |
| `inconsistent_active_minutes` | Минуты, для которых активная мощность превысила выбранный ориентир с допуском | 0 |

### 2. Расчёт по дням в summarize(minutes)

`resample("D")` группирует `active_kw` по календарным датам. Каждое значение относится к интервалу длиной 1/60 часа, поэтому энергия за измеренную часть дня в кВт·ч равна сумме минутных значений в кВт, делённой на 60. Например, первая минута архива имеет мощность 4,216 кВт. Её вклад составляет 4,216 / 60 ≈ 0,07027 кВт·ч.

| Колонка в daily.csv | Расчёт |
|---|---|
| `day` | Календарная дата в формате `ГГГГ-ММ-ДД`. Используются метки из исходника без перевода часового пояса. |
| `valid_minutes` | Количество минут с числовым значением активной мощности. |
| `coverage_pct` | `100 × valid_minutes / 1440`. Для этого набора базой служат 24 часа по 60 минут. |
| `observed_kwh` | Энергия за минуты с показаниями. `sum(min_count=1)` оставляет пустое значение при полном отсутствии измерений. |
| `full_day_kwh` | Суточная энергия. Заполняется только при наличии всех 1 440 минут. |

17 декабря 2006 года в архиве есть все 1 440 показаний. За этот день измерено **56,50767 кВт·ч**. Днём ранее запись началась в 17:24, поэтому за 16 декабря доступны лишь 396 минут, или 27,5 % суток. Измеренный расход за этот отрезок составляет **20,15293 кВт·ч**. Полный расход за 16 декабря неизвестен. За 29 апреля 2007 года нет ни одной пригодной минуты, и обе колонки с энергией пусты.

### 3. Запись и командная строка

`prepare(source, output)` вызывает обе функции и создаёт целевую папку. Минутная таблица записывается в CSV порциями по 50 000 строк. Для очистки исходная таблица загружается в оперативную память целиком. Все три CSV сначала формируются во временной папке и затем по одному заменяют одноимённые файлы результата.

`main()` разбирает параметры через `argparse`, запускает подготовку и печатает число строк, календарных дней и полных суток. Без аргументов скрипт ищет TXT в `data/raw/` и сохраняет результаты в `data/`. Ошибка чтения файла или разбора данных выводится в терминал. Блок `if __name__ == "__main__"` в каждом скрипте запускает его при прямом вызове. Благодаря этому тесты могут импортировать функции отдельно.

## Как работает plot.py

1. `main()` читает `daily.csv` с помощью pandas, разбирает даты, сортирует их и сообщает доступные границы. По умолчанию путь определяется относительно самого скрипта. Для другой таблицы служит `--data`.
2. `choose_date(...)` проверяет каждую границу. Если аргумент не задан, функция запрашивает дату в терминале. Нажатие Enter выбирает первую доступную дату для начала и последнюю для конца. При ошибке ввода приглашение повторяется. Неверная дата в аргументе командной строки завершает запуск с сообщением. Последний день может совпадать с первым.
3. Срез `daily.loc[str(start):str(end)]` включает обе даты. В терминал выводятся расход за минуты с показаниями, если такие минуты есть, и число полностью измеренных суток.
4. `read_minutes(daily_path, start, end)` ищет `minutes.csv` в папке переданного суточного CSV. Если его там нет, используется `minutes.zip`. Функция читает только `timestamp` и `active_kw` порциями по 100 000 строк и оставляет показания от полуночи первой даты до полуночи после последней, исключая правую границу. Время становится индексом. Метод `asfreq("min")` добавляет отсутствующие минутные метки между показаниями, сохраняя пропуски. Поэтому линия разрывается на участке без измерений.
5. `draw(days, minutes, output, show)` строит верхнюю панель в **кВт**. Светло-синяя линия показывает минутные показания и позволяет увидеть короткие всплески. Тёмно-синяя показывает среднюю мощность за каждый час. Для часовой точки нужны все 60 минут с измерениями, поэтому пропуск даже одной минуты оставляет пробел в часовом ряду.
6. На нижней панели бирюзовый столбец показывает энергию за полные сутки в **кВт·ч**. Неполная дата остаётся без столбца. Измеренный расход и долю покрытия за неё можно посмотреть в `observed_kwh` и `coverage_pct` суточной таблицы. Если в выбранном периоде до 21 дня включительно, над столбцами видны подписи, округлённые до десятых кВт·ч. Когда подходящих показаний за весь период нет, панель выводит пояснение.
7. Рисунок сохраняется в `plots/energy_ГГГГ-ММ-ДД_ГГГГ-ММ-ДД.png`. Повторный запуск для тех же дат обновляет этот файл. По умолчанию скрипт также открывает окно с графиком, если графическая среда доступна. Параметр `--no-show` позволяет ограничиться сохранением.

## Запуск и самопроверка

После установки зависимостей откройте терминал в папке проекта. Команды ниже предполагают, что `python` запускает интерпретатор с установленными зависимостями.

```powershell
python plot.py
python plot.py --start 2006-12-22 --end 2006-12-28 --no-show
```

Второй вызов воспроизводит график за семь полных дней. По нижней панели видно, что наибольший расход за неделю пришёлся на 23 декабря (79,56 кВт·ч), а наименьший — на 27 декабря (25,48 кВт·ч). Верхняя панель за эти же даты показывает, как распределялась нагрузка внутри суток.

При изменении правил очистки пересоберите CSV. В первом примере используется распакованный TXT из стандартной папки. Во втором путь к архиву и папка для результата заданы явно.

```powershell
python prepare.py
python prepare.py "$env:USERPROFILE\Downloads\archive.zip" --output data/rebuilt
python plot.py --data data/rebuilt/daily.csv --start 2007-04-29 --end 2007-04-29 --no-show
```

Для автоматической проверки достаточно стандартного модуля Python `unittest`.

```powershell
python -m unittest -v test_prepare
```

Первый набор примеров проверяет слияние повторов, сохранение согласованных показаний и исключение конфликтов. Второй проверяет обработку испорченных полей, нуля и физически возможного пика. Третий создаёт полные сутки с постоянной мощностью 2 кВт, пропущенные сутки и день с одной измеренной минутой. Для полных суток ожидается 2 × 24 = 48 кВт·ч, для пропущенных — пустая энергия, а для измеренной минуты с нулевой нагрузкой — 0 кВт·ч. Эти тесты работают без исходного архива.
